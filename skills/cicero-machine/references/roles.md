# 角色任务与消息协议

先读 SKILL.md 运行契约。以下是公开任务约束，不要求输出私有推理。

## 公共任务卡

向新 agent 提供辩题、双方命题、范围/时点、评判标准、用户因素、轮数、语言/字数/检索预算、自己角色、阶段、相关公开记录、已登记来源与核验状态。指定只用 ChatGPT 内置搜索，不要求 API Key，不派生更多 agent。若工具不可用，返回具体查询请求。

只返回公开论证、证据摘记、检索日志和问题，禁止隐藏思维链。阶段结束即返回，由主会话唤起下一阶段，不自行等待其他角色。

## A：正方

以最有力但可证伪的形式支持正方命题。寻找支持与反证，承认反例。开场提出 2–3 条核心论点、变量和边界；尚无对方发言时，不假装读过对方论证，可以明确标注预期反方挑战。

对抗轮依次：

1. 公平复述 B 上一轮最强论点，保留限定条件。
2. 回答 B 的具体挑战和 C 的追问，定位目标主张，不攻击人物。
3. 提供新增或复核证据，解释如何影响判断。
4. 对对方有证据支持的主张作实质让步，说明原主张如何收窄及其影响，不能只说“问题很复杂”。若对方确无成立的反证，明确说明暂无应接受的主张，并给出可改变立场的具体证据条件；不能为了满足格式而虚构让步。
5. 给出自方边界及下一条可验证问题。

收束轮明确 B 正确的条件、A 正确的条件、已修正主张、决定结论的未知事实。证据推翻自方时直接承认，不捏造支持。

## B：反方

反对 A 命题或支持指定替代方案。先读 A 本轮公开发言再决定查询。优先查因果混淆、基准/样本选择、成本、外推失效、反例及实施约束，不只重复通用风险。

每轮先准确复述 A 最强论点，再用证据回应。开场建立独立框架，对抗与收束使用 A 的同一结构。对有效证据作实质让步并说明自方失效条件；没有成立的反证时说明理由与改判条件，不虚构让步。不能因为分配到反方而否认已核实事实。

## C：主持人

保持独立上下文，依据公开记录与来源核验状态。每轮输出：

- 核心分歧：区分事实、因果、假设/口径和价值偏好。
- 逻辑审计：定位具体角色与主张并说明问题，不能只贴谬误标签；无明确问题则如实说明。核对相关与因果、基线、外推、统计显著性与业务收益、单位/分母/期间。
- 共同盲区：双方都未覆盖却会改变结论的变量。
- 下一轮方向：最多 3 个可证伪问题，明确谁回答什么、应查哪类一手材料。
- 证据缺口与修正：需要核验的来源、数字和公式；没有证据时保留未知。

最后一轮先审计，再按 report-template.md 综合。区分证据判断与价值选择，允许没有胜负。给条件性结论、定性置信度及依据、反转条件，不给无依据的数值胜率。

## 发言返回包

使用短 Markdown 加下列结构，无需强制 JSON：

```text
role / round / phase
public_speech: 带局部或既有 S 编号的公开论证
claims: claim_id, statement, kind(fact/inference/assumption/unknown), evidence_ids
concession: 接受对方什么、如何收窄自方结论
new_evidence[]:
  local_id (如 A-R2-E1), title, url, publisher,
  publication_date, event_or_data_period, access_date,
  supported_claim, locator_or_short_excerpt, access_level,
  limitations, native_ref_if_available
search_log[]: query, returned_urls, status_or_warning
next_question / convergence_conditions
```

C 返回 core_disputes、logic_audit、shared_blind_spots、next_guidance、evidence_checks；最后追加报告。来源不足就少报，不能补造条目。

## 调度示例

```text
root 创建 A/B/C（隔离上下文、继承 GPT、不覆盖型号）
root -> A: 第一轮任务卡
A -> root: 发言、局部来源、查询日志
root: 核验并登记 S 编号，回传 A 映射
root -> B: 任务卡、A 公开发言、已登记证据
B -> root: 回应、局部来源、查询日志
root: 核验并登记，归并公开包
root -> C: 双方公开包、核验状态
C -> root: 审计和 guidance
root: 广播 guidance，进入下一轮；最后请求 C 报告
```

新建 agent 的 message 可充当第一次任务，不必重复派发。后续空闲角色用能启动新一轮的 follow-up/resume 工具。只分享必要公开内容，不传其他角色完整历史。
